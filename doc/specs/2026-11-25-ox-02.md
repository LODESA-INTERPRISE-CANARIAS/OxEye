## 1. Objective

Decide and document where each piece of data lives and which domain owns it, so that map, materials, dates and costs read the same information instead of drifting copies. The output is a set of Architecture Decision Records plus a data-authority map, not an implementation.

## 2. Scope

### In scope

1. `ADR-024-001` Physical architecture — options A/B/C compared (cost, effort, risk, OX tasks blocked or limited per option).
2. `ADR-024-002` Authoritative database — engine choice, environments, migrations, security, operation, cost.
3. `ADR-024-005` Offline mode — operations allowed without network vs. operations that require the server.
4. Data-authority map — 20 entities, one owner domain each, read/write roles, current location in v0.16.0, and the OX-03..OX-22 cross-check.
5. Transition strategy — coexistence of the current local mode with a future server: `Ojo_de_Buey_Proyecto.json` v1 import, schema versioning, stable identifiers.
6. Plan B without server budget — what the pilot can demonstrate locally, with its limits stated honestly.
7. Monthly cost estimate per option, explicitly labelled as an estimate with date and sources.

### Out of scope

- Any change to `src/`, `tests/`, configuration, dependencies or `.claude/`.
- Removing the unused `drizzle-orm` dependency or `src/db/schema.ts` (recorded as a follow-up for OX-21/OX-24).
- ADR-024-003, -004, -006 .. -011 (only referenced where they interact).
- Choosing a concrete hosting provider contract (stays conditional on budget, per the 24/11 meeting).
- Fixing KI-01..03, KI-05, KI-06, KI-07, KI-28 (referenced as constraints only).

### 4.2 Draft recommendations (to be confirmed in review)

- **ADR-024-001:** approve the *logical* architecture now — one modular backend (option B) with domain modules; heavy simulation stays in the browser (deterministic, local data). Keep the *physical* infrastructure conditional on budget. Option C (managed Postgres-based BaaS) is evaluated as the cheapest route to B-compatible storage, provided business rules and authorization do not end up in the browser (INV-011, TEC-004). Option A is the documented plan B, not the target.
- **ADR-024-002:** PostgreSQL (+ PostGIS evaluated for geometry, decision deferred to ADR-024-003) as authoritative store, EU-region hosting for GDPR. Browser storage (Dexie) becomes cache/drafts only. The unused SQLite Drizzle schema is not the target model; removal proposed as follow-up.
- **ADR-024-005:** offline = consultation, drafting, local simulation and export. Requires server: confirming reservations, commitments/economic state changes, sending communications, role/permission changes, closing real incidents, publishing a layout version. Drafts carry `draft` state and a base version; on reconnect, optimistic version check (INV-004), never silent overwrite.

Each row in the final document also states: readers, writers, current location in v0.16.0, sensitivity (Punto Violeta, personal data), and offline behaviour. Simulated incidents remain owned by Simulation and never become real incidents (INV-009).

### 4.4 Transition strategy (outline)

1. Introduce stable UUIDs for every entity; derive deterministic ids for legacy items on import (e.g. from venue key + index) so re-importing the same file does not duplicate (INV-019).
2. Version the file format (`version: 2`) with an explicit migration chain `v1 → v2`; keep v1 import working.
3. A v1 JSON is imported as one Project + one Event per scene with content.
4. Dates stored as ISO-8601 instants plus `Atlantic/Canary` as the event time zone (TEC-006).
5. Local mode continues to work unchanged until the server exists; once it exists, the server copy is authoritative and the browser keeps cache and drafts (TEC-007).

### 4.5 Cost estimate

Monthly ranges for A (≈0 €), B (small VPS or managed Postgres + app hosting in EU) and C (BaaS free/pro tiers), from public pricing pages consulted during execution, with date and links, labelled *Estimación — no es un presupuesto*. Generic queries only; no project or personal data sent.

## 5. Domain invariants affected

No code changes, so no runtime invariant can regress. The documents must:

- Punto Violeta: state that sensitive data is excluded from public views and exports, and that shared storage of it requires an explicit privacy decision (INV-018) — listed as an open product decision, not resolved by the AI Lead.
- `EventDemandConfig`: keep it as the single demand source inside the Event/Distribution, and name it as the precedent to generalise.
- Simulation reproducibility: the engine keeps running on local data with the scenario seed regardless of the option chosen.
- Non-certification wording: costs and capacities are estimates; nothing is presented as regulatory compliance.
- Secrets never in browser code or exports (INTG-009).
