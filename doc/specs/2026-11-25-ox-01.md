## 4. Scope

### In scope

1. **Audit document** `doc/audit/2026-11-25-ox-01-audit.md` (written in English; Spanish UI terms kept verbatim), containing:
   - Classification of every module in `src/engine/` (63) and `src/components/` (42), plus `src/store/`, `src/db/`, `src/data/`, `src/App.tsx`, with the [ESP] §20.13 scale and the evidence for each status (tests, call sites). A button or export alone never yields "Existente y verificado".
   - Real architecture: layers, cross-domain imports, import cycles, boundary leaks (`store → components`, `engine → store`, engine → data/DOM), and where state is persisted (`localStorage` keys, Dexie tables, JSON export/import) and what each holds.
   - Dependency inventory (runtime and dev), with used/unused status and evidence.
   - Known-issues register with severity (blocker / high / medium / low) and cause, including all items in section 3.
   - Gap matrix with the [ESP] §20.14 columns for the capabilities touched by OX-02 to OX-24 (see input I1). The matrix only records state and gaps; it does not plan or start any of those tasks.
   - Invariant map: for each of the five invariants (routes A/B/C, Carpa Amarilla, Punto Violeta privacy, X-ray and 500 kg/m², `EventDemandConfig` attendance conservation) at least one current test, or a registered gap.
   - Verification log: every command, date, commit, counts and exit code.
   - Proposed corrections for `README.md` and `doc/claude/02_ARQUITECTURA_Y_STACK.md` / `04_ESTADO_ACTUAL.md` and the `package.json` version, as proposals only.
2. **Install and run instructions**: rewrite the `README.md` section "🚀 Inicio Rápido" (Spanish, like the rest of the README) so a newcomer can follow it alone: Node version, `npm ci`, `npx playwright install chromium`, `npm run dev`, the checks, and the generated artefacts. No other README section changes.
3. **E2E repair** under `tests/e2e/**` only: update selectors and the first-run setup to the current flow (create a project through the wizard or seed state the way the app does). A test that cannot pass without an app change is marked `test.fixme(...)` with the reason and registered as a known issue. No assertion is removed or weakened to obtain a green run.
4. **Cleanup** (D1): remove the 124 unused `eslint-disable` directives. Comment-only edits. Because the hooks block `--fix`, the edits are made file by file from the lint report, or by the user running `npm run lint:fix` personally (user's choice at execution time; see 7.3).
5. **Artefact tracking** (D2): the user adds `playwright-report/` and `test-results/` to `.gitignore` (protected path, not writable by Claude). Claude runs `git rm -r --cached playwright-report test-results`; if the hooks block it, the user runs it. Local files stay on disk.

### Out of scope

- Prettier formatting, enabling `strict` (OX-24), removing `drizzle-orm`, `drizzle-kit` or `gts`, breaking import cycles, any refactor, any change to `src/**` other than D1 comment removal, CI changes (adding E2E to CI), version bump, editing `doc/claude/**`, `doc/CHANGES-PLAN.md` or `CLAUDE.md`.
- Deleting or disabling any simulation or emergency module.
- Any push or remote operation (CLAUDE.md §8.1). Local merge into `main` needs a separate instruction.
